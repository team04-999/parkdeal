# Pleos 설계 가이드 중 우리가 따르는 것

공모전 심사는 App Market 입점 심사가 아니다([`contest.md`](contest.md)). 그래서 이 문서는 입점 심사 준비물을 다루지 않는다.
Pleos 설계 가이드에서 **공모전 평가와 2차 PT 시연에 영향이 있는 규칙만** 골랐다.

가이드를 따르는 이유는 두 가지다.

- **차량특화성**: "주행 중엔 이렇게, 정차하면 이렇게"를 가이드 근거로 설명할 수 있으면, 모바일 앱을 차에 옮긴 것이 아니라는 증거가 된다
- **기술 활용성·PT Q&A**: SDK·차량 API를 어떤 기준으로 골랐는지 팀이 직접 답해야 한다

출처: [앱 설계 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/intro), [UI Design Guide](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro). 정리일 2026-11-13, 에뮬레이터 v2.1.0 기준.
문장은 요약이고 숫자 기준은 원문 그대로다. 판단이 애매하면 원문을 연다.

## 1. 주행 중과 정차 중

앱의 핵심 시나리오(P단 진입 → 브리핑, 출차)가 여기에 걸려 있다.

| 규칙 | ParkDeal에서 |
|---|---|
| Distraction Optimization 선언이 없는 앱은 주행 중 쓸 수 없고 정차 중에만 쓸 수 있다 | 선언한다(2026-11-15 변경). 주행 제한 중에는 고른 곳 하나와 짧은 목록만 보여주고, 체류 시간 선택·지도·긴 글은 숨긴다. 첫 안내는 음성으로 한다. 이유는 [`architecture.md`](architecture.md) |
| 주행 제한 상태는 `CarUxRestrictions` 로 확인하고 제한된 UI를 줄이거나 막는다 | 화면을 줄이는 기준은 기어 값이 아니라 `CarUxRestrictionsManager` 로 한다. 기어는 "주차 세션 시작·종료" 판단에만 쓴다 |
| 오디오는 Audio Focus 정책을 따른다 | TTS 안내 전에 포커스를 요청하고 끝나면 반납한다. 내비 음성 안내와 겹치지 않게 한다 |
| 주행 중 영상, 장식·반복 애니메이션, 자동 텍스트 스크롤 금지 | 주행 중에 바뀌는 화면 요소를 두지 않는다 |
| 알림은 운전에 필요할 때만 짧게 보낸다. 광고 금지 (텍스트 광고는 광고주·상품명만) | **매장 딜은 주행 중에 알리지 않는다.** 정차 후 주차 정보와 함께 "이 주차장에서 할인되는 곳"으로 보여준다. 사업성 설명도 광고가 아니라 주차 할인 정보로 한다 |
| 주행 중 행동 데이터를 마케팅에 쓰지 않는다 | 딜 추천에는 현재 목적지와 주차 위치만 쓴다 |

## 2. 조작과 화면

2차 PT에서 심사위원이 에뮬레이터 화면을 직접 본다. 심사 장소가 UX스튜디오다.

| 기준 | 값 |
|---|---|
| 정보 파악 시간 | 1~2초 안에 핵심을 알 수 있게 한다 |
| 조작 | 한 손 조작. 터치를 줄이고 음성(STT)을 쓴다. 검색은 키보드보다 최근 목적지·프리셋·음성 |
| 메뉴 | 자주 쓰는 기능을 첫 화면에 둔다. 드롭다운·다단계 메뉴를 남용하지 않는다 |
| 음성 | 대화는 핸즈프리로 하되 시작·종료·중단은 손으로도 할 수 있게 한다 |
| 입력 응답 | 터치 후 0.25초 안에 시각 피드백. 넘으면 진행 중 표시. 버튼 동작은 2초, 실행·로드는 10초 안 |
| 대비 | 텍스트·아이콘 4.5:1 이상 |
| 텍스트 | 3줄 이하, 한 줄 80자 이하(영어 기준) |
| 글자 크기 | 핵심 정보 5mm 이상, 보조 3mm 이상. 최소 12sp |
| 폰트·아이콘 | Asta Sans. 아이콘은 48×48dp 그리드에 텍스트 라벨을 붙인다 |
| 토스트 | 앱 패널 안 좌우·아래 여백 24, 최대 폭 792 |

버튼 크기와 색상 값은 원문에 이미지로만 있다. UI Design Resources의 Figma 파일을 본다.

## 3. 창과 생명주기

Pleos 화면은 Driving view(내비) 옆에 앱이 최대 2개 붙는다. 에뮬레이터에서도 그대로 보인다.

| 규칙 | ParkDeal에서 |
|---|---|
| 세로·가로 레이아웃을 각각 설계한다. 기본은 세로 1창 | 세로 1창(1:1 분할)을 기본으로 만든다. 가로는 시간이 남으면 |
| 창 크기가 바뀌어도 깨지지 않고 같은 기능을 쓸 수 있다 | 시연 전에 분할 비율을 바꿔 확인한다 |
| 화면에서 나가도 종료되지 않는다. 다시 앞으로 오면 마지막 상태를 복원한다 | 주차 세션은 프로세스가 다시 만들어져도 남게 저장한다. 시연 중 앱을 전환해도 세션이 살아 있어야 한다 |
| 백그라운드에서는 화면 갱신·타이머·폴링을 줄인다. 주행 중 CPU 5% 미만, 메모리 400MB 이하 | 기어는 리스너로만 받는다. 프로토타입의 5초 폴링을 넣지 않는다 |

## 4. 차량 API 고르는 기준

PT 기술 Q&A에서 "왜 이 API를 썼나"에 답하는 근거다. 쓸 수 있는 SDK 범위는 [`contest.md`](contest.md)를 따른다.

| 규칙 | ParkDeal에서 |
|---|---|
| 기어·속도 같은 표준 차량 데이터는 AAOS Car API(`CarPropertyManager`)를 먼저 쓰고, OEM 전용 기능은 Pleos SDK를 쓴다 (권장) | 기어는 Vehicle SDK로 읽는다. 기어 입력을 인터페이스로 분리해 양산 탑재 때 `CarPropertyManager` 로 바꿀 수 있게 한다. 이유는 [`architecture.md`](architecture.md#기어는-pleos-vehicle-sdk로-읽는다-2026-11-13) |
| 차종마다 지원이 다르다. `checkXXXCapabilities`·`isSupported` 로 확인하고 차종명으로 분기하지 않는다 | 기어·위치 지원 여부를 확인하고, 없으면 수동으로 주차를 시작하게 한다 |
| NaviHelper는 내비 탑재 차량에서만 완전 호환, FusedLocation은 차종별(`isSupported`), TTS·STT는 완전 호환 | 핵심 경로는 TTS·STT로 만들고 NaviHelper·FusedLocation은 지원 확인 뒤 쓴다 |
| 오프라인·저대역폭 대비: 캐시, 타임아웃 있는 재시도, 오프라인 안내 (권장) | 시연장 인터넷이 불안정할 수 있다. 주차장 목록을 캐시해서 서버가 응답하지 않아도 시연이 된다 |

## 다루지 않는 것

입점 심사용 항목은 수상 후 App Market 탑재를 준비할 때 본다: [앱 보안 가이드](https://document.pleos.ai/docs/pleos-only/app-registration-guide/app-security-guide), [App Review Guidelines](https://document.pleos.ai/docs/pleos-only/distribute/app-review-guide), [앱 심사 제출](https://document.pleos.ai/docs/pleos-only/distribute/app-submission-guide).
