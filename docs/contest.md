| 사업성 | 타깃 고객, 사용자 확보·유지·확대 가능성 (타깃 분석, 예상 MAU, Retention, 확대 계획) |

## 개발 범위와 기술 규칙

공지 「공모전 개발 범위 및 기술 문의 안내」가 기준이다.

- **현재 공개된 Pleos Playground 개발 문서의 SDK·API 범위에서만 개발한다.** 문서에 없는 기능은 쓸 수 없고, 필요하면 기획서에 향후 계획으로 적는다
- 쓸 수 있는 SDK: Vehicle, NaviHelper, TextToSpeech, SpeechToText, FusedLocation. 워크스페이스에 '준비 중'으로 떠도 문서대로 에뮬레이터에서 개발·시험 가능
- 공개되지 않은 SDK와 **Pleos LLM SDK는 제공되지 않는다**
- **공모전 참가팀은 Gleo Interface(App Schema) 검토·승인을 신청할 수 없다**
- **차량 마이크 음성을 외부 음성 인식 서비스로 보내면 안 된다.** 음성 인식은 SpeechToText SDK로
- 외부 API와 공용 네트워크는 쓸 수 있다 (설명회 기술 Q&A)
- SDK 권한: 개발·공모전 단계에서는 승인 절차 없이 매니페스트에 문서의 user permission만 선언하면 된다. 승인 여부는 실제 App Market 배포 심사 때 본다
- 심사는 App Market 입점 심사가 아니다
- 2차 PT 시연은 **에뮬레이터 구동 화면 또는 기기 시연**. 실차 시연은 지원하지 않는다. 장비·인터넷 등은 본선 진출팀에 따로 안내
- 개발 환경: Android API 28 이상, Gradle 8.0 이상, Java 또는 Kotlin
- 장비 대여, 실차 측정 장소, 기술 지원 창구는 없다. 기술 문의는 Playground 문서로, 운영 문의만 메일로

## ParkDeal에 미치는 영향

1. **Gleo 연동을 핵심 기능으로 기대면 위험하다.** 프로토타입에서 `schema.json`을 등록해 에뮬레이터 호출까지 확인했지만, 참가팀은 Gleo Interface 승인을 신청할 수 없다. 에뮬레이터 데모는 가능해도 "공개 문서 범위" 해석에 따라 감점이나 실격 소지가 있으니 운영사무국에 문의해 확인하고, 음성 대화의 주 경로는 **SpeechToText + TextToSpeech SDK**로 옮기는 것을 검토한다
2. **음성 인식은 STT SDK만.** 외부 음성 인식 API는 쓰지 않는다
3. **외부 API는 쓸 수 있다.** 서울 열린데이터 실시간 주차 가능 대수 같은 외부 데이터를 앱에서 직접 불러올 수 있다
4. **가산점 일정과 새 레포가 겹친다.** 11/15 마감 메일에 저장소 주소와 커밋 해시를 적어야 가산점을 받는다. 새 레포는 아직 비어 있으므로 마감 전에 동작하는 소스 + release APK를 올릴지 정해야 한다. 1차 산출물은 PT 전까지 자유롭게 고도화할 수 있으니, 1차에는 프로토타입을 정리해 올리고 PT 전까지 새 구조로 다시 만드는 방법도 있다
5. **PT 기술 Q&A에서 팀이 구조를 직접 설명해야 한다.** 새 레포를 처음부터 하나씩 잡는 방향과 잘 맞는다
6. **차량특화성이 첫 평가 항목.** 기어(P/D) 맥락, 내비 목적지, 음성 같은 "차라서 되는 것"을 핵심 시나리오의 중심에 둔다
7. **주행 중 화면 차단 (Activity Distraction).** 프로토타입에서 D단일 때 앱 화면이 막혔다. 설명회 기술 Q&A에서도 질문이 나왔지만 답변이 불분명했다. 주행 중 경험은 음성·알림 중심으로 설계하고, 시연 시나리오도 이에 맞춘다
